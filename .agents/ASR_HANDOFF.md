# ASR handoff

Updated: 2026-08-28

The ASR direction and executable delivery plan are in `docs/ASR_PLAN.md`. The decision is synchronized into `AGENTS.md`, `Codex.me`, `.agents/feature_list.json`, `.agents/progress.md`, `.agents/CHANGELOG.md`, and `.agents/experience.md`.

Before implementation, read that document completely. Continue from `ASR-4`; do not add provider-side ad hoc downloads or concrete engine imports to Pipeline or Worker. The default-engine decision remains gated by the EvoBlue benchmark, artifact-level licensing review and mainland-China download-path verification.

ASR-1 is complete. Lite Zipformer and Standard SenseVoice load and transcribe real Chinese audio on Windows; the 60-minute bounded-segment test and real cancellation + checkpoint/resume verification pass. Do not restore `SKIP_ENVIRONMENT` for installed models.

ASR-2 is complete. The manifest/download contracts are frozen; resumable safe installation, atomic activation and the WebUI model-management flow (list/install/cancel/uninstall) are implemented; mainland-China source qualification is delivered as "machinery + evidence, no mirror yet" (see `docs/ASR_CHINA_SOURCE_QUALIFICATION.md`). Both production manifests are `upstream_only`: the SenseVoice archive points to FunASR Model License 1.1, the exact Zipformer archive carries no license file. No unapproved mirror may enter a production manifest.

ASR-3 is complete, including four acceptance-review hardening rounds. Routing is language-aware and user-pinnable; missing models enter persisted `waiting_for_model` with one explicit recommendation and no hidden download. All job resumption goes through `reconcile_waiting_asr_jobs()` (`asr/service.py`), which is double-gated on the SQLite install record AND a registered provider. Its three trigger points are engine startup (closing the crash window between an install commit and the resume), a completed install, and saving `whisper_cpp_executable` in settings (a CLI configured after the model now unblocks parked jobs). `PUT /api/settings` rejects any `asr_provider` outside the four-value Literal. Provider registration (`asr/registration.py`) is an expected-state reconcile: a changed CLI replaces the old provider, a cleared CLI or deleted model files unregister what this module registered, ownership is tracked per concrete instance so external registrations are never removed, uninstalling a model drops its engine immediately, and a failing model load is isolated — the tier stays unregistered (with a known-bad marker retried only on event paths) so one corrupt model can never block engine startup. The Silero VAD is a bundled managed dependency (`asr/assets/`, pinned SHA verified in `asr/vad.py`): recognition archives ship no VAD, and the entire resource path sits inside a fault boundary — a missing, unreadable, or hash-mismatched asset logs a stable error code and resolves to "tiers not ready" instead of failing engine startup. Load-failure logs are sanitized to provider id, stable error code, and exception type. The full Silero MIT license text ships with the package (`asr/assets/silero_vad.LICENSE`, also in THIRD_PARTY_NOTICES.md) — this closes the release-gate item on bundled-license text early; ASR-4 packaging still verifies it ships in the wheel. SenseVoice languages stay on Standard/Lite, other languages recommend optional `whisper-cpp-base`; Markdown records actual provider/model/version. Lite remains installable and explicitly selectable but is not a formal default recommendation. ASR-4 must run the benchmark/release gates before marking any tier as formally approved default.

`docs/ASR_PLAN.md` is the detailed source of truth. Harness files contain only the routing, status and durable guardrails needed for normal agent startup.
