## 已知问题

- **初始设置未完成时任务恒 `queued` 且零用户可见提示**（2026-09-06 WorkBuddy 真机实测暴露）：`ProductionHandlerFactory` 在 `setup_completed=false` / LLM 四要素缺失 / keyring 取不到凭据时返回 None，worker 循环按设计不捡任务（`runtime/bootstrap.py`）——任务永久停在 queued/progress=0/stage=null，客户端只能靠 `diagnose_environment` 的 `llm_config` warning 反推原因。行为本身正确（不捡完不成的任务；worker 每轮 claim 前重读设置，设置完成后队列任务自动开跑），缺的是反馈：候选改进（P5/P8）——status 响应或诊断消息直接给出「Worker 空闲原因：初始设置未完成」。
- MCP Python SDK v2（锁定 mcp 2.0.0）已接入；传输层约束留档 ADR 0004：outputSchema 顶层 `type:object` 强制 → 信封以 JSON 文本交付（预案 A）；参数模型默认 `extra=ignore` → Bridge 收紧为 forbid；httpx 代理环境变量会截胡 loopback → `trust_env=False`。
- SenseVoice 的 1.05 GB 完整包包含 FP32 + INT8；生产 Manifest 只能指向 INT8-only 制品，并分别记录实测下载体积与安装体积。
- SenseVoice 精确归档指向 FunASR Model License 1.1，不是 Apache-2.0；Lite Zipformer 精确归档未携带许可证文件。两者的镜像再分发须在 ASR-2 留证审批，未过门禁前只能作为候选。
- Windows 自带/系统安装的旧 `C:\Windows\System32\onnxruntime.dll` 可能抢先于 sherpa 加载；不得把 C API version 报错误判为模型版本。Provider 必须在导入 sherpa 前固定项目 ASR 环境的 ONNX Runtime DLL 目录。
